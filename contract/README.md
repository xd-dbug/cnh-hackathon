Owned by D (human). Agents read `schema.sql` and `examples/*.json` but never edit them.
These are the rules the JSON can't express.

## Routes
| Route | Success |
|---|---|
| `POST /conferences` body `{url, timezone?}` | 202 + Conference when a job was queued, 200 + Conference when the URL is already known |
| `GET /conferences` | 200 `{conferences: Conference[]}` |
| `GET /conferences/:cid` | 200 Conference |
| `GET /conferences/:cid/talks?q=&day=` | 200 `{talks: Talk[]}` |
| `POST /conferences/:cid/clashes` body `{starred}` | 200 `{clashes: {a, b}[]}` |
| `GET /conferences/:cid/alternatives?talk=&starred=&level=` | 200 `{alternatives: (Talk & {score})[]}` |

## IDs
- A conference ID is generated by the API: `^[a-z0-9]{10}$`.
- A talk ID is the source's own ID as an opaque string: `^[A-Za-z0-9_-]{1,64}$`. It is unique
  within its conference only. Never parse it as a number.
- "Sort by id" means plain string comparison (JavaScript's default `<`, Postgres `COLLATE "C"`).

## Errors
- Every 4xx body is `{"error": "<message>"}`.
- 400: a malformed ID, `day`, `level`, `url`, `timezone` or JSON body.
- 404: an unknown `:cid`, or an unknown `talk` on `/alternatives`.
- 409: `talks`, `clashes` or `alternatives` on a conference whose `status` isn't `ready`.
- 429: too many `POST /conferences` from one client.
- Ignore unknown IDs in `starred`, so stale localStorage can't break the page.

## Conferences
- `status` moves `queued → fetching → parsing → embedding → ready`, or to `failed` from any stage.
  `error` is present only when `failed`, and is a sentence a user can read.
- `name`, `platform`, `timezone`, `talkCount` and `scrapedAt` appear once known. `ready` always has
  `name`, `timezone` and `talkCount`.
- `days` lists the dates (`YYYY-MM-DD`, in the conference's timezone) that have at least one talk,
  ascending. `levels` lists the distinct `level` values, sorted. Both are `[]` until `ready`.
- `GET /conferences` lists only `ready` conferences, sorted by first day descending, then `id`.
- `POST /conferences`:
  - `url` must be `http` or `https`, at most 2048 characters. A host that is literally `localhost`
    or a private, loopback or link-local IP returns 400. (The worker re-checks after DNS and on
    every redirect, and fails the job if any hop resolves to such an address.)
  - The URL is normalised before dedupe: lowercase the scheme and host, drop the default port and
    the fragment. Path and query are kept as they are.
  - An already-known URL returns that conference with 200, unless it is `failed`, which is
    re-queued (202).
  - `timezone` is optional, an IANA name (`America/Denver`), else 400. The worker uses it only
    when the source has no timezone of its own.

## Talks
- Times are ISO 8601 with the conference's UTC offset at that instant:
  `YYYY-MM-DDTHH:mm:ss±HH:MM`. So a conference that spans a DST change shows two offsets.
- `day` is `YYYY-MM-DD`, meaning that calendar day in the conference's timezone. Any other format
  returns 400.
- No pagination. Without `q`, return up to 2000 talks sorted by `start`, then `id`. With `q`,
  return up to 50 sorted by relevance. `day` filters both, and without `day` they cover every day.
- Missing strings are omitted and missing arrays are `[]`. `abstract`, `url`, `room`, `venue`,
  `track` and `level` may all be absent (see `1335605` in `talks.json`); clients must handle that.
- `url` is the talk's official page, when the source has one.

## Clashes
- Two talks clash when `a.start < b.end && b.start < a.end`. Touching talks don't clash.
- Each pair appears once, with `a` starting first (`id` breaks ties). Sort pairs by `a.start`,
  then `a.id`, then `b.id`.
- An empty or missing `starred` returns `{"clashes": []}`. At most 100 IDs, else 400.

## Alternatives
- At most 5 talks, sorted by `score` descending: the most similar talks (by title + abstract) that
  clash with no starred talk other than `talk`. The results never include `talk` or any starred ID.
- `level`, if given, must be one of the conference's `levels`, else 400. It filters the results.
- No matches is `{"alternatives": []}`, not 404. So is a `talk` with no embedding.
- `score` is cosine similarity and only for ranking, so don't display it as a percentage.
